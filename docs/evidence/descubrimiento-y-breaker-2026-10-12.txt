4. CIRCUIT BREAKER / LIMITE DE TASA EN EL GATEWAY: 429 CON Retry-After
-----------------------------------------------------------------------

Se puso GATEWAY_RATE_LIMIT_PER_MINUTE=3 en el .env, se recreo el gateway y se verifico que
el contenedor lo recibio. Despues se hicieron cuatro peticiones seguidas con una API key
de prueba (la clave no se imprime).

gateway: healthy
tope aplicado: 3
=== cuatro curl a /v1/auth/verify
request 1 -> 200
request 2 -> 200
request 3 -> 200
retry-after: 60
request 4 -> 429

Resultado: las tres primeras peticiones pasan; la cuarta recibe 429 rate_limited con
Retry-After. Despues se quito la variable del .env y se recreo el gateway (queda el valor
por defecto, 300 por minuto, fijado por la prueba "is 300 per minute").

Nota de procedimiento: un primer intento con la variable solo en el shell
(GATEWAY_RATE_LIMIT_PER_MINUTE=3 docker compose ...) no llego al contenedor (printenv
salio vacio) y las cuatro peticiones dieron 200; por eso se repitio por el .env. El
resultado valido es el de arriba.

6. LIMITES CONOCIDOS
--------------------

  se reinician con el proceso y no se comparten entre replicas.
- Cada instancia de un servicio tiene sus propios Circuit Breakers (no compartidos).
- Reports todavia no filtra los analisis por tenant (aviso para el Area 4).
